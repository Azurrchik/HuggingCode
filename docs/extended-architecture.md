# Архитектура расширенного HuggingCode

## Назначение

Этот документ описывает самостоятельные возможности HuggingCode, вдохновлённые распространёнными рабочими процессами терминальных coding agents. Он не является спецификацией и не использует закрытый код, брендинг или удалённую инфраструктуру других продуктов.

## Карта команд

| Категория | Команды HuggingCode | Реализация |
|---|---|---|
| Сессия | `/clear`, `/rename`, `/resume`, `/branch`, `/export`, `/rewind` | Локальные снимки сообщений в каталоге конфигурации пользователя. |
| Контекст | `/context`, `/compact`, `/autocompact`, `/btw` | Подсчёт сообщений и приблизительных токенов; локальное резюме диалога. |
| Планирование | `/plan`, `/goal`, `/verify` | Режим без изменений, Markdown-чек-лист и запуск проверок после подтверждения. |
| Рабочая область | `/init`, `/memory`, `/add-dir`, `/cd`, `/diff` | Проектный `HUGGINGCODE.md`, явно добавленные корни, смена рабочей папки, Git diff. |
| Права | `/permissions`, `/mode` | Независимые режимы manual, accept-edits, plan и safe-auto. Небезопасный bypass-режим отсутствует. |
| Модель | `/model`, `/effort`, `/usage` | Модель, `reasoning_effort` при поддержке модели и накопленная статистика ответа. |
| Диагностика | `/status`, `/doctor`, `/debug` | Состояние, проверка окружения и журнал событий без секретов. |
| Проверки | `/review`, `/security-review`, `/simplify`, `/run`, `/verify` | Подготовленные задания агенту, использующие обычные подтверждённые инструменты. |
| Параллельная работа | `/subtask`, `/tasks`, `/stop` | Локальные задачи в рамках запущенной сессии; без фоновых демонов и внешних worktree/PR-автоматизаций. |
| Пользовательские навыки | `/skills`, `/reload-skills`, `/skill <name>` | Markdown-шаблоны из `.huggingcode/skills`. |

## Границы безопасности

HuggingCode всегда блокирует доступ за пределы доверенных рабочих каталогов и `.env`-подобные файлы. Режим `manual` требует подтверждения любой записи и команды. Режим `accept-edits` автоматически разрешает только обычные записи в проекте. Режим `plan` отклоняет любые записи и команды. Режим `safe-auto` допускает только консервативный список безопасных команд и только операции в проекте; удаление, сеть, перенаправления, цепочки команд и команды с повышенными правами всё равно требуют подтверждения либо блокируются.

## Компоненты

`config.js` хранит пользовательские параметры. `session-store.js` сохраняет снимки диалогов. `workspace.js` владеет границами путей, Git и файловыми инструментами. `permissions.js` принимает решение по действию. `skills.js` загружает пользовательские Markdown-навыки. `tasks.js` регистрирует локальные асинхронные задачи. `agent.js` ведёт сессию, контекст и вызовы модели. `ui.js` сопоставляет slash-команды с этими компонентами.

## Явно не реализуемые закрытые или инфраструктурные функции

В эту локальную версию не включаются облачные сессии, удалённое управление, авторизация у сторонних продуктов, их биллинг, фирменные плагины, подключение сторонних учётных записей, автоматическое создание pull request, веб-агенты, постоянные демоны, бесконтрольное выполнение команд и обход подтверждений. Такие функции требуют собственной инфраструктуры, аккаунтов, явной настройки интеграций и отдельной модели угроз.
