# HuggingCode 0.3 — Interactive TUI Foundation

## Цель

HuggingCode 0.3 превращает текущий последовательный CLI в самостоятельный интерактивный терминальный coding agent. Цель не в копировании интерфейса другого продукта, а в превосходящем UX для Hugging Face-first сценария: пользователь всегда понимает состояние агента, может остановить или поставить в очередь работу, безопасно подтверждает изменения и способен откатить сделанные агентом правки.

## Непереговорные принципы

| Принцип | Решение |
|---|---|
| Наблюдаемость | Любой turn отображает timeline сообщений, мыслительных статусов, инструментов, согласований, команд и проверок. |
| Безопасность по умолчанию | Не будет глобального bypass. Сохраняются `manual`, `accept-edits`, `plan`, `safe-auto`, секретные пути и boundary рабочей области. |
| Отмена и восстановление | Пользователь может отменить запрос и откатить поддержанные правки файлов по checkpoint. |
| Hugging Face-first | Модели вызываются удалённо; UI показывает модель, capabilities, usage, контекст и статус сети. |
| Локальность | Сессии, checkpoints и настройки остаются на компьютере пользователя; attachment не передаётся, пока пользователь не отправит сообщение. |
| Доступность | Полная клавиатурная навигация, русский и английский интерфейсы, понятные цвета без единственного цветового канала. |

## Обязательные пользовательские потоки

### 1. Рабочий turn

Пользователь вводит задание в multiline composer. Пока агент работает, transcript дополняется потоковыми событиями; composer принимает следующее сообщение и показывает размер очереди. `Esc` предлагает отменить текущий turn. Пользователь видит активные tool calls и финальный summary с изменёнными файлами и проверками.

### 2. Разрешение действия

Вместо последовательности note/confirm отображается permission card. Карточка показывает action type, путь, причину, классификацию риска и diff или preview. `Y` разрешает один раз, `N` запрещает, а безопасные классы могут быть добавлены в локальное allow rule отдельным контролом. В `plan` режимe write/command вообще не предлагаются.

### 3. Откат

Перед поддержанным write, replace и delete создаётся checkpoint с исходным содержимым и fingerprint. `/undo` восстанавливает последний checkpoint текущего turn, но не перезаписывает файл, вручную изменённый после действия; вместо этого создаёт conflict report.

### 4. Проверка

После edit интерфейс предлагает найденные lint/test/typecheck/build команды. Запуск всегда проходит через существующие permission rules. Результат отображается в transcript и связан с turn.

### 5. Сессии и контекст

Status bar показывает mode, model, context usage, token usage и состояние задачи. Session picker содержит title, workspace, updated time, model/mode, turn count и search/filter. При приближении к configurable context threshold интерфейс показывает заметную, но ненавязчивую рекомендацию compaction.

## Целевой интерфейс

```text
╭─ HuggingCode ─ workspace: my-project ──────────────────────────────────────╮
│ user  › исправь обработку невалидного токена                                │
│ agent › читаю src/auth.js                                                    │
│ tool  › read_file src/auth.js                                                │
│ edit  › src/auth.js                                  [просмотр diff]         │
│ verify› npm test                                                             │
│ agent › Исправил обработку ошибки. 1 файл изменён, тесты пройдены.           │
├─────────────────────────────────────────────────────────────────────────────┤
│ model: gpt-oss-120b · mode: manual · ctx: 18% · tokens: 3.4k · idle          │
╰─ › /review auth ────────────────────────────────────────────────────────────╯
```

Структура должна адаптироваться к маленьким терминалам: transcript получает приоритет, sidebar не используется, а status bar сжимается до essential labels.

## Техническая стратегия

1. Отделить presentation layer от current `ui.js`: runtime/controller, state machine transcript, input model и render adapter.
2. Использовать React + Ink для полноценного TUI. Существующие security/workspace/session modules остаются доменной логикой и не должны дублироваться в компонентах.
3. Добавить streaming adapter поверх Hugging Face Inference Client. Если конкретный provider/model не поддерживает stream, UI отображает determinate «waiting» state и затем final response без нарушения event contract.
4. Завести typed event protocol: `turn_started`, `text_delta`, `thinking_delta`, `tool_started`, `tool_result`, `approval_requested`, `verification_*`, `turn_finished`, `turn_cancelled`, `error`.
5. Test-first покрыть reducer transcript, queue, permission decisions, checkpoint conflicts и command detection.

## Не входит в 0.3

Облачные сессии, произвольный MCP без отдельной threat model, бессрочные background daemons, неограниченный auto-approve, копирование фирменных UI-компонентов, чужих строк или брендинга. Эти направления могут оцениваться после устойчивого TUI-контракта.

## Критерии готовности

| Область | Измеримый результат |
|---|---|
| TUI | Нет блокирующего `p.text` main loop; transcript/input/status — отдельные компоненты. |
| Работа агента | Text и tool progress видны до финального ответа при доступном streaming. |
| Control | Esc cancel, input history, command completion и message queue работают в тестах. |
| Safety | Все существующие boundary/secret/mode tests сохраняются; permission card добавляет, а не заменяет policy. |
| Recovery | `/undo` корректно восстанавливает последний поддержанный change либо объясняет конфликт. |
| Verification | Common Node/TypeScript/Python checks обнаруживаются и требуют approval согласно mode. |
| Quality | Lint, test, smoke TUI и npm package dry-run проходят. |
