# Команды HuggingCode

HuggingCode реализует самостоятельные локальные команды, ориентированные на общие сценарии терминального coding agent: работа с контекстом, моделью, разрешениями, планами, Git-диффом, памятью проекта и сохранёнными сессиями. Список основан на публично описанных категориях команд Claude Code, но реализация HuggingCode независима и не является копией другого CLI.[1]

## Работа с сессией и контекстом

| Команда | Назначение |
|---|---|
| `/clear [name]`, `/reset`, `/new` | Сохраняет текущую сессию и начинает новую с пустым контекстом. |
| `/rename <name>` | Переименовывает текущую сохранённую сессию. |
| `/resume [id]`, `/continue` | Показывает последние сессии или возобновляет сессию по ID. |
| `/branch [name]` | Создаёт локальную ветку сессии, не меняя Git-ветку. |
| `/rewind [N]`, `/checkpoint`, `/undo` | Восстанавливает N-ю последнюю локальную контрольную точку контекста. Не откатывает файлы. |
| `/export [file.md]` | Экспортирует переписку в Markdown после применения текущего режима разрешений. |
| `/context` | Показывает число сообщений и приблизительную оценку объёма контекста. |
| `/compact [focus]` | Просит выбранную модель сжать историю до рабочего резюме. |
| `/autocompact [auto\|число]` | Настраивает порог подсказки о необходимости сжатия контекста. |
| `/btw <вопрос>` | Задаёт side-вопрос без записи ответа в основную историю. |
| `/goal <условие>`, `/goal clear` | Сохраняет цель сессии и добавляет её к следующим заданиям. |

## Модель, использование и разрешения

| Команда | Назначение |
|---|---|
| `/model [model-id]` | Показывает или сохраняет модель Hugging Face для новых запросов. |
| `/effort [auto\|none\|minimal\|low\|medium\|high\|xhigh]` | Настраивает `reasoning_effort`, если выбранная модель его поддерживает. |
| `/usage`, `/cost`, `/stats` | Показывает накопленные токены ответов текущей сессии; не оценивает цену. |
| `/mode [mode]` | Быстро переключает режим разрешений. |
| `/permissions`, `/allowed-tools` | Показывает доступные режимы и позволяет установить режим аргументом. |
| `/config [key=value ...]`, `/settings` | Просматривает или сохраняет конфигурацию. |
| `/color [name]`, `/theme [name]` | Сохраняет цвет баннера следующего запуска. |
| `/debug [on\|off]` | Переключает локальный диагностический вывод. |
| `/status` | Показывает модель, режим, рабочую область, сессию и расположение хранилища. |
| `/doctor`, `/checkup` | Проверяет Node.js, Git, настройки, сессии и навыки. |

> Режим `safe-auto` **не** является неограниченным режимом. Он разрешает только обычные записи в рабочей области и очень небольшой список безопасных проверочных команд. Удаление, сеть, цепочки shell-команд, перенаправления и опасные операции не получают автоматического разрешения.

| Режим | Поведение |
|---|---|
| `manual` | Каждая запись, удаление и команда требует подтверждения. |
| `accept-edits` | Обычные записи в проекте выполняются без диалога; команды и удаления подтверждаются. |
| `plan` | Разрешено только исследование: записи, удаления и команды блокируются. |
| `safe-auto` | Обычные записи и фиксированный небольшой набор проверок выполняются автоматически; прочее запрашивает подтверждение. |

## Проект и качество кода

| Команда | Назначение |
|---|---|
| `/init` | Создаёт `HUGGINGCODE.md` — локальную память и соглашения проекта. |
| `/memory`, `/memory add <текст>` | Просматривает или дополняет память проекта. |
| `/plan [задача]` | Включает режим `plan` и строит план без изменений файлов. |
| `/diff` | Показывает Git diff текущей рабочей области. |
| `/review`, `/code-review` | Выполняет read-only обзор текущего diff через модель. |
| `/security-review` | Выполняет read-only проверку текущих изменений на распространённые риски безопасности. |
| `/simplify [focus]` | Ищет точки упрощения и дублирование без применения правок. |
| `/run`, `/verify [target]` | Просит агента подобрать и выполнить релевантные проверки после нужных подтверждений. |
| `/batch <задача>` | Разбивает крупную задачу в план работ без облачных worktree и pull request. |
| `/add-dir <path>` | После явного подтверждения добавляет дополнительный доверенный каталог только к текущей сессии. |
| `/cd <path>` | После подтверждения переносит сессию в другую основную рабочую область. |

## Навыки и локальные подзадачи

| Команда | Назначение |
|---|---|
| `/skills`, `/reload-skills` | Сканирует `.huggingcode/skills/*.md` и выводит доступные навыки. |
| `/skill <name> [arguments]` | Запускает выбранный Markdown-навык. Его `$ARGUMENTS` заменяется аргументами команды. |
| `/<skill-name> [arguments]` | Короткая форма запуска найденного навыка. |
| `/subtask <задача>` | Запускает локальную исследовательскую подзадачу, пока открыт текущий процесс. |
| `/tasks`, `/bashes`, `/agents`, `/list-agents` | Показывает локальные подзадачи и их результаты. |
| `/stop <task-id>` | Останавливает регистрацию результата локальной подзадачи. |

Пример навыка:

```markdown
---
description: Кратко проверить изменения
---

Review $ARGUMENTS. Read the diff and related files. Do not make changes.
```

Сохраните его как `.huggingcode/skills/review.md`, затем вызовите `/review auth flow`.

## Аутентификация и выход

| Команда | Назначение |
|---|---|
| `/login` | Проверяет и заменяет сохранённый Hugging Face token. |
| `/logout` | Удаляет локально сохранённый зашифрованный токен. |
| `/help` | Выводит краткую справку. |
| `/exit`, `/quit` | Сохраняет сессию и выходит. |

## Внешние или намеренно не реализованные функции

Некоторые публично документированные команды стороннего продукта зависят от его облачных сервисов, OAuth, подписки, удалённого управления, MCP-серверов, фирменных плагинов, облачных worktree, GitHub/Slack-приложений, браузерных агентов или постоянных фоновых процессов. Такие компоненты нельзя честно перенести в независимый локальный CLI без отдельной инфраструктуры, согласий и учётных данных. HuggingCode показывает понятное сообщение и предлагает локальный аналог вместо того, чтобы имитировать их работу.

К этой группе относятся, например, облачные сессии и перенос между устройствами, удалённые агенты, сторонние OAuth-входы, управление плагинами и MCP, автоматическое исправление pull request, облачное планирование по расписанию, голосовой ввод и небезопасный обход защит. Документация внешнего продукта отдельно отмечает, что доступность команд может отличаться в зависимости от платформы, плана и окружения.[1]
