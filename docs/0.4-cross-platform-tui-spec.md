# HuggingCode 0.4 — Cross-Platform Interactive UX

## Цель

HuggingCode 0.4 делает CLI полноценным ежедневным инструментом для работы с кодом на **Windows, Linux и macOS**, сохраняя локальные границы рабочей области и принцип explicit approval. Интерфейс остаётся самостоятельным: он использует общие проверенные паттерны terminal coding agent, но не копирует чужую фирменную разметку, названия или закрытые реализации.

## Платформенная модель

| ОС | Защищённое хранение токена | Запуск shell-команд | Поведение без системного secret store |
|---|---|---|---|
| Windows | DPAPI через PowerShell | `cmd.exe /d /s /c` | Не требуется fallback. |
| macOS | Keychain через `security` | `/bin/sh -lc` | Токен остаётся только в текущей сессии при ошибке Keychain. |
| Linux | Secret Service через `secret-tool` | `/bin/sh -lc` | Токен остаётся только в текущей сессии, если Secret Service недоступен. |

HuggingCode не записывает незашифрованный токен на диск в качестве fallback. При отсутствии поддерживаемого secret store пользователь вводит токен при новом запуске.

## Model catalog и picker

Каталог читает `GET https://router.huggingface.co/v1/models` с токеном Hugging Face. Он сохраняет только неперсональные метаданные в памяти процесса: идентификатор, владелец, контекст, максимальные output tokens, поддерживаемые capabilities, provider и доступные policy suffixes. Каталог не записывает токен, ответы модели или историю выбора в проект.

Picker вызывается командой `/model` без аргумента или сочетанием `Ctrl+M`. Он поддерживает поиск по ID, фильтры `code`, `vision`, `tools`, просмотр метаданных и переключение модели по `Enter`. Клавиши `←` и `→` выбирают policy `fastest`, `cheapest` или `preferred`. Ручной идентификатор доступен через `/model <id> [policy]`.

## Typed full mode

`/mode full` не меняет настройки сразу. Controller открывает отдельный overlay с предупреждением и требует точную фразу `ENABLE FULL MODE`. После успешного подтверждения full mode действует только в runtime текущей сессии и заметно маркируется в header/status bar.

Full mode убирает диалог подтверждения для обычных изменений, удалений и неадминистративных команд **только внутри выбранного workspace**. Он не снимает физические границы workspace, запрет обхода символьных ссылок или блокировку чтения и записи секретных файлов. При закрытии CLI режим исчезает и не сохраняется в конфигурацию.

## Keyboard-first layout

Интерфейс состоит из четырёх закреплённых зон. Верхняя строка показывает workspace, активную модель, permission mode и состояние turn. Центральный scrollback показывает сообщения, streaming, tool calls и результаты. Permission и diff cards отображаются прямо в transcript и получают фокус только пока ожидают решения. Внизу composer поддерживает несколько строк и командную палитру.

| Клавиша | Действие |
|---|---|
| `Enter` | Отправить задачу или применить выбранный пункт palette/picker. |
| `Shift+Enter` | Новая строка в composer. |
| `Esc` | Отменить streaming turn, закрыть palette или отклонить pending approval. |
| `Ctrl+M` | Открыть model picker. |
| `Ctrl+P` | Открыть command palette. |
| `Ctrl+L` | Очистить видимый transcript без удаления сохранённой сессии. |
| `Ctrl+C` / `Ctrl+D` | Безопасно закрыть приложение. |
| `↑` / `↓` | История ввода, либо навигация в palette/picker. |

## Acceptance criteria

1. Пакет запускается на Node.js 22+ в Windows, Linux и macOS без Windows-only import или shell requirement.
2. На Linux и macOS токен не сохраняется в открытом виде. При недоступности secret store CLI остаётся работоспособным в session-only режиме.
3. Пользователь может найти модель, просмотреть capabilities и изменить модель без ручного копирования ID.
4. Tool operation, concise diff-preview и verification остаются различимыми в transcript, а approval не требует чтения неструктурированного лога.
5. Full mode требует точную фразу, всегда заметен в интерфейсе, не персистируется и не ослабляет workspace/secret boundaries.
6. `npm run lint` и `npm test` проходят в Linux; platform-specific paths покрыты mock-тестами.
