# Архитектура HuggingCode 0.3

## Граница ответственности

Существующие `storage.js`, `config.js`, `permissions.js`, `session-store.js`, `skills.js` и `workspace.js` остаются доменными слоями. Новый TUI не должен обходить их policy или читать секреты напрямую. Он запрашивает действие у controller, controller — у agent/workspace, а решение разрешения возвращается через отдельный UI overlay.

```text
bin/huggingcode.js
        │
        ▼
src/tui/start.js ──► src/tui/App.js
        │                 │
        │                 ├── transcript reducer / queue / input
        │                 ├── status bar / picker / permission card
        │                 └── controller callbacks
        ▼
src/controller.js
        │
        ├── CodingAgent (streaming events + cancellation)
        ├── Workspace (bounded tools)
        ├── Permission policy
        ├── Checkpoint store
        ├── Verification detector
        └── Session store / skills / config
```

## Event contract

```js
{ type: 'turn_started', turnId, prompt }
{ type: 'text_delta', turnId, text }
{ type: 'thinking_delta', turnId, text }
{ type: 'tool_started', turnId, tool, input }
{ type: 'tool_result', turnId, tool, output, durationMs }
{ type: 'approval_requested', turnId, action, preview }
{ type: 'verification_suggested', turnId, commands }
{ type: 'verification_result', turnId, command, result }
{ type: 'turn_finished', turnId, summary, usage }
{ type: 'turn_cancelled', turnId }
{ type: 'error', turnId, message }
```

Every event is safe to render: terminal control characters are stripped and previews are bounded. Full file contents and secret paths never enter a UI event.

## Streaming protocol

Hugging Face `chatCompletionStream` returns SSE chunks. The agent aggregates delta content, tool-call fragments and final usage. It emits `text_delta` as chunks arrive. If the selected model/provider rejects streaming, the client emits a `stream_fallback` notice and uses the existing non-streaming completion path; the transcript still shows a waiting state.

Cancellation is controller-level and uses an `AbortController`. The adapter passes a signal when the installed client supports it; otherwise cancellation stops future tool rounds, hides the live row and marks the turn cancelled without pretending a completed response is valid.

## Security constraints

- Permission policy remains the source of truth; `PermissionCard` cannot authorize a policy-denied action.
- `allow once` returns only a one-turn grant. No global bypass mode is introduced.
- Checkpoints are stored under the HuggingCode configuration area with `0600` equivalent file permissions, not in the project or Git tree.
- Verification commands run only through existing `safe-auto`/approval policy.
- Attachments are metadata until user submits; `.env`, key and credential patterns use the existing deny rules.

## Migration

1. Add Ink runtime dependencies and raise the Node floor to 22.
2. Add UI components and pure reducers with unit tests before switching the entrypoint.
3. Keep existing slash-command semantics through a controller adapter.
4. Move agent from final-only completion to event-driven streaming.
5. Add checkpoint and verification layers under existing workspace policy.
6. Retire `src/ui.js` only after CLI smoke tests cover onboarding, `/help`, denied writes, cancellation and session resume.
